# Combined HTTP/2 application-error evidence

[combined-application-errors.tar.gz](combined-application-errors.tar.gz) contains
reviewed source and pure in-memory public-codec evidence for three application
error schedules. The [manifest](manifest.json) binds archive identity and all
27 current module hashes. `INVENTORY.json` binds every other member's size and
SHA-256; all members are regular UTF-8 files with safe relative paths.

The archive includes the pushed 25-module B5c baseline, current/failure snapshots,
unchanged initial/final test, selection RED, per-case reset-completion REDs, all
34 current normal/optimized command receipts, input identities, source review
and Root audits. The parser/upload sources used to resolve the callback-span
review question are included alongside immutable fixture and family references.

Exact J/C/R is 11/10/48, 11/10/48 and 10/9/65, with six new persistent records.
The supported source subset is 31/40; nine selections still fail before actions.
Each test mode has six positive executions and 64 postimplementation synthetic
sensitivity controls. Behavioral RED is finite supplied-input exhaustion after
reset processing, not a native hang. The path-alias metadata audit failure is
retained; no source/test threshold was changed to correct it.

The audit distinguishes 119 retained identity rows from 114 unique entries and
checks all 42 pinned codec files. Commands, pinned Python and model/core/helper
identities are in the archived implementation report. Source and licenses are
included; native binaries/cache are excluded. Supplied peer records do not prove
Zig callback or native fixture behavior. Full40/default/aggregate/runtime/native,
project gates and source adoption remain unverified. See the
[focused report](../../m2_h2_combined_application_errors.md).
